# Спецификация пользовательского интерфейса (UI/UX) и стайлгайд :: Inventory DSS

**Версия**: 3.5.0 (Production-Ready Architecture)  
**Целевая платформа**: Система поддержки принятия решений по управлению запасами (Mission-Critical Logistics Cockpit)  
**Эстетический канон**: Промышленный Необрутализм (Industrial Neo-Brutalism)  
**Нормативный базис**: W3C Design Tokens Community Group (DTCG), WCAG 2.2 AA (Контрастность и доступность), Web Interface Guidelines  
**Машиночитаемые токены**: `inventory_dss/tokens/tokens.json`, `inventory_dss/tokens/tokens.css`, `inventory_dss/tokens/tokens.scss`

## 1. Введение и философия: Промышленный Необрутализм

Интерфейс **Inventory DSS** спроектирован по принципам промышленного необрутализма для оперативных диспетчеров, аналитиков цепей поставок и директоров по логистике. СППР управляет физическими запасами на складе с жесткими ресурсными ограничениями ($V_{\max} = 1000\text{ м}^3, W_{\max} = 50\text{ т}$), поэтому каждый элемент интерфейса лишен декоративного шума и оптимизирован под безошибочное принятие решений в условиях высокой цены ошибки.

### 1.1 Фундаментальные принципы интерфейса
1. **Жесткие физические тени без размытия (0-Blur Hard Offset Shadows)**:
   - Полный отказ от рассеянных гауссовых теней;
   - Физические проекции со сдвигом: `box-shadow: 4px 4px 0px #000000;`;
   - Ощущение овеществленности и аппаратной надежности каждого блока.
2. **Бескомпромиссные механические контуры (Machinery Borders 2–3px)**:
   - Четкие рамки `border: 2px solid var(--border-default)`;
   - Контрастное разделение панелей и сайдбара: `border-right: 3px solid var(--border-default)`.
3. **Тактильный механический отклик (Mechanical Switch Press)**:
   - Элементы управления физически «продавливаются» в точку тени при взаимодействии:
     - `hover`: `transform: translate(-1px, -1px); box-shadow: 5px 5px 0px #000;`
     - `active / pressed`: `transform: translate(2px, 2px); box-shadow: 1px 1px 0px #000;`
4. **Промышленная сигнальная палитра (High-Vis Safety & Hazard)**:
   - Яркие контрастные маркеры: Safety Orange (`#FF5500`), Warning Yellow (`#F59E0B`), Radar Green (`#10B981`), Crimson Hazard (`#EF4444`);
   - Предупреждающая диагональная черно-красная штриховка при критической перегрузке склада ($>95\%$).
5. **Моноширинная точность (Tabular Numerals First)**:
   - Все числовые показатели, SKU, ROP, партии и финансовые суммы зафиксированы моноширинным шрифтом со свойствами `font-variant-numeric: tabular-nums lining-nums; font-feature-settings: "tnum" 1, "zero" 1;`.
6. **Штампы-маркировки (Stencil Badges)**:
   - Прямоугольные бейджи со скруглением $2\text{px}$, жирным шрифтом и рамкой: `[ CRITICAL // P1 ]`.
7. **Концентрические радиусы скругления (Concentric Radii)**:
   - Соблюдение математического правила соосности: $R_{\text{outer}} = R_{\text{inner}} + \text{Padding}$. При карточке с радиусом $6\text{px}$ и внутренним паддингом $12\text{px}$ вложенный элемент имеет радиус $2\text{px}$.

## 2. Архитектура дизайн-токенов и доступность (WCAG 2.2 AA)

Дизайн-система построена на 3-уровневой иерархии токенов:
1. **Primitives**: базовые числовые и цветовые константы (Zinc, Slate, Emerald, Crimson, Amber, Indigo, размеры, отступы).
2. **Semantics**: функциональные токены контекста (`--surface-canvas`, `--text-primary`, `--status-critical-bg`, `--glow-optimal`).
3. **Components**: токены конкретных виджетов (`--kpi-card-border`, `--matrix-cell-ax-bg`, `--slider-track-fill`).

## 3. Детальные спецификации 5 ключевых экранов СППР

Все экраны строятся на базе 12-колоночной адаптивной сетки (Desktop $\ge 1440\text{px}$, Tablet $1024\text{px}$, Mobile $768\text{px}$) с базовой единицей сетки $8\text{px}$ и межколоночным зазором (gutter) $16\text{px}$.

---

### Экран 1: Сводка KPI и триаж оперативных действий (Executive KPI Overview & Action Triage)

**Назначение**: Главный экран оперативного руководства. Обеспечивает мгновенную оценку состояния склада, выявление дефицитов и перегрузок по принципу Management-by-Exception (управление по отклонениям).

#### Сетка и компоновка (12 колонок):
1. **Строка 0 (Колонки 1–12, высота 40px)**: Индустриальная телеметрическая строка диспетчера (`Global Dispatch Ticker`):
   - ID склада (`WH-MAIN-01`), процент заполнения объема ($V_{\text{used}} / V_{\max}$), загрузка по весу ($W_{\text{used}} / W_{\max}$), число дефицитных SKU, уровень сервиса $\alpha$, индикатор режима работы.
2. **Строка 1 (Колонки 1–12)**: Сетка из 5 Hero KPI карточек (по 2.4 колонки / flex 1):
   - Карточка 1: **Стоимость запасов на складе** ($\sum I_i \cdot C_i$ в млн ₽, дельта к прошлой неделе).
   - Карточка 2: **Затраты на хранение в год** ($18\%$ от стоимости запасов, дельта).
   - Карточка 3: **Фактический уровень сервиса** ($\alpha$, целевой $95.0\%$, дельта в п.п.).
   - Карточка 4: **Позиции в дефиците** (SKU со статусом `CRITICAL`, пульсирующий красный бейдж).
   - Карточка 5: **Позиции к заказу** (SKU со статусом `REORDER`, янтарный бейдж).
3. **Строка 2 (Колонки 1–8 / Колонки 9–12)**:
   - **Колонки 1–8**: Блок оперативного триажа (Netstock Action Triage):
     - 4 таба/корзины: `[ ДЕФИЦИТ: DOI < L ]`, `[ ПЕРЕЗАКАЗ: I_eff <= ROP ]`, `[ ИЗБЫТОК: DOI > 120д ]`, `[ НОРМА ]`.
     - Список топ-3 неотложных действий с кнопками быстрого одобрения заказа.
   - **Колонки 9–12**: Спирометры физической емкости склада:
     - Объем склада ($V_{\text{used}}$ против $1000\text{ м}^3$).
     - Весовая нагрузка ($W_{\text{used}}$ против $50\text{ т}$).
     - Пороги индикации: зеленый ($<80\%$), янтарный ($80-95\%$), красно-черная штриховка ($\ge 95\%$).
4. **Строка 3 (Колонки 1–7 / Колонки 8–12)**:
   - **Колонки 1–7**: Таблица очереди приоритетных заказов (SKU, наименование, поставщик, объем, сумма, кнопка действия).
   - **Колонки 8–12**: Аналитика структуры TCO (совокупной стоимости владения): горизонтальный бар категорий и донат-чарт (хранение, заказы, штраф за дефицит).

### Экран 2: Здоровье запасов и интерактивная матрица ABC/XYZ

**Назначение**: Сегментация номенклатуры по ценности выручки (ABC) и регулярности спроса (XYZ) для выбора дифференцированных стратегий управления.

#### Сетка и компоновка (12 колонок):
1. **Строка 1 (Колонки 1–12)**: Глобальная панель мульти-фильтров:
   - Выпадающие списки: Категория (Все / Электроника / Инструменты и т.д.), Класс ABC, Класс XYZ, Статус запаса.
2. **Строка 2 (Колонки 1–7 / Колонки 8–12)**:
   - **Колонки 1–7**: Интерактивная 9-квадрантная сетка ABC/XYZ (3×3 карточки):
     - Ряды: A (80% выручки), B (15% выручки), C (5% выручки).
     - Колонки: X ($CV < 0.15$), Y ($0.15 \le CV \le 0.35$), Z ($CV > 0.35$).
     - Каждая ячейка отображает: класс (напр., `AX`), число SKU, суммарную стоимость (₽), процент капитала.
     - Интерактивность: клик по ячейке фильтрует таблицу внизу.
   - **Колонки 8–12**: 2D Scatter-плот распределения номенклатуры:
     - Ось X: Коэффициент вариации спроса ($CV$).
     - Ось Y: Накопленная доля выручки (%).
     - Размер точки: Стоимость запаса в рублях.
     - Цвет: Семантический статус запаса (`OPTIMAL`, `REORDER`, `CRITICAL`, `EXCESS`).
3. **Строка 3 (Колонки 1–12)**: Детализированный реестр SKU:
   - Высокоплотная таблица со `sticky` заголовком, постраничной пагинацией и кнопкой экспорта `[ Экспорт CSV ]`.
   - Колонки: SKU, Наименование, Категория, ABC, XYZ, Текущий остаток, Страховой запас (SS), Точка заказа (ROP), Статус, Стоимость.

### Экран 3: Предиктивная аналитика спроса и доверительные интервалы

**Назначение**: Прогнозирование временных рядов потребности, декомпозиция тренда/сезонности и оценка неопределенности спроса методом веерных диаграмм (Fan Chart).

#### Сетка и компоновка (12 колонок):
1. **Строка 1 (Колонки 1–4 / Колонки 5–12)**:
   - **Колонки 1–4**: Селектор фокусного SKU с карточкой метаданных:
     - Выбор SKU из каталога, средний дневной спрос ($\mu_D$), волатильность ($\sigma_D$), тип динамики (стабильный, трендовый, сезонный, прерывистый по Кростону).
   - **Колонки 5–12**: Метрики точности конкурирующих моделей:
     - Сравнительные плашки: WAPE, MAPE, RMSE, R² для Baseline, Ridge Regression, Holt-Winters и LightGBM/Ensemble.
2. **Строка 2 (Колонки 1–12, высота 420px)**: Веерный график прогноза (Confidence Fan Chart):
   - Исторические продажи (сплошная линия Slate-200).
   - Точечный прогноз на горизонт планирования (яркая линия Safety Orange / Cyan).
   - Доверительный интервал 95% ($\pm 1.96 \sigma_{\text{forecast}}$) в виде полупрозрачной заливки с четкими пунктирными границами.
   - Вертикальная линия-маркер точки разделения истории и прогноза (`T_now`).
3. **Строка 3 (Колонки 1–6 / Колонки 7–12)**:
   - **Колонки 1–6**: Декомпозиция временного ряда (графики тренда, недельной и месячной сезонности).
   - **Колонки 7–12**: Диагностика остатков прогноза (гистограмма ошибок с проверкой нормальности распределения для формулы страхового запаса).

### Экран 4: Радар поставщиков и оценка рисков срыва поставок

**Назначение**: Многокритериальная оценка надежности контрагентов (MCDA / AHP + TOPSIS) и расчет сценариев срыва поставок с деревом решений (EMV).

#### Сетка и компоновка (12 колонок):
1. **Строка 1 (Колонки 1–4 / Колонки 5–12)**:
   - **Колонки 1–4**: Панель весов критериев (AHP/TOPSIS):
     - Слайдеры настройки важности: Срок поставки ($LT$), Надежность (OTIF %), Процент брака, Ценовая надбавка, Мин. партия (MOQ).
     - Индикатор согласованности матрицы Саати ($CR < 0.10$).
   - **Колонки 5–12**: Лепестковая диаграмма (6-Axis Spider/Radar Chart):
     - Нормализованные лепестки сравнения 5 поставщиков. Полупрозрачные контрастные заливки.
2. **Строка 2 (Колонки 1–7 / Колонки 8–12)**:
   - **Колонки 1–7**: Рейтинговая таблица поставщиков:
     - Ранг, Наименование, Профиль надежности, Срок ($L \pm \sigma_L$), OTIF, Брак, Итоговый балл близости TOPSIS ($C_i \in [0, 1]$).
   - **Колонки 8–12**: Дерево решений рисков срыва поставок (Supply Disruption EMV Tree):
     - Интерактивное сравнение стратегий: Single Sourcing против Dual Sourcing.
     - Параметры: вероятность срыва $p$, стоимость простоя/штрафа.
     - Вывод: Ожидаемая денежная оценка (EMV) каждой стратегии и точка безубыточности $p^*$.

### Экран 5: Рабочее место ЛПР по пополнению и What-If симуляция

**Назначение**: Интерактивный верстак для формирования и утверждения партий заказов с учетом складских лимитов и объяснимого ИИ (XAI).

#### Сетка и компоновка (12 колонок):
1. **Строка 1 (Колонки 1–12)**: Панель What-If параметров сценария (в сворачиваемом контейнере):
   - Слайдер целевого уровня сервиса $\alpha \in [90.0\%, 99.9\%]$.
   - Слайдер шока срока поставки $\Delta LT \in [0, 14\text{ дней}]$.
   - Поля лимитов склада $V_{\max}$ и $W_{\max}$.
   - Кнопка: `[ Пересчитать сценарий ]`.
2. **Строка 2 (Колонки 1–12)**: Индикаторы дельты сценария (Scenario Diffs):
   - 4 сравнительные плашки: $\Delta$ Инвестиций в закупку, $\Delta$ Занимаемого объема, $\Delta$ Страхового запаса, $\Delta$ Риска дефицита.
   - Индикатор перегрузки склада с вызовом алгоритма пропорционального усечения заказов (KKT-оптимизация).
3. **Строка 3 (Колонки 1–8 / Колонки 9–12)**:
   - **Колонки 1–8**: Интерактивная таблица утверждения заказов (PO Approval Queue):
     - SKU, Наименование, Оптимальная партия ($Q^*$), Срок поставки, Сумма, Чекбокс подтверждения.
     - Кнопка действия: `[ Утвердить выбранные заказы (PO) ]` и `[ Экспорт в 1C:ERP (JSON/CSV) ]`.
   - **Колонки 9–12**: Карточка объяснимого ИИ (XAI Reasoning Card):
     - Бейдж уровня доверия: `[ ALGORITHMIC: EOQ + Wagner-Whitin ]`.
     - Факторы решения: вклад волатильности спроса, влияние срока поставки поставщика, ограничение минимальной партии (MOQ).
     - Текстовое обоснование на естественном языке с формулой расчета.
4. **Строка 4 (Колонки 1–12)**: Логистический планировщик паллетизации:
   - Расчет требуемого автотранспорта (еврофуры 82 м³, 20 т), коэффициенты заполнения по объему и весу, правила сборных поставок (FTL / LTL).

## 4. Каталог компонентов и матрица 8 интерактивных состояний

Каждый из 9 ключевых компонентов специфицирован во всех 8 интерактивных состояниях:
1. `default`: базовое состояние покоя.
2. `hover`: наведение курсора мыши.
3. `active / pressed`: момент нажатия (физическое продавливание).
4. `focus`: доступность с клавиатуры (WCAG 2.4.7 focus ring 2px Indigo с отступом 2px).
5. `disabled`: заблокированный элемент (прозрачность 40%, курсор not-allowed).
6. `loading / skeleton`: состояние ожидания пересчета (пульсирующий шиммер Slate-800 -> Slate-700).
7. `empty`: отсутствие данных / нулевой результат фильтрации (понятный плейсхолдер с подсказкой).
8. `error`: ошибка валидации / выход за физические границы (контур Crimson, поясняющий текст ошибки).

## 5. Дорожная карта интеграции и технологическая гибкость

Пользователь согласовал гибкость технологического стека. Предлагается два взаимодополняющих сценария интеграции:

### Сценарий A (Базовый / In-Place): Нативный Streamlit 1.35+ с инъекцией CSS и токенов
- **Трудоемкость**: Низкая (1–2 дня).
- **Архитектура**:
  1. Подключение токенов через `src/inventory_dss/ui/theme.py`: генерация `<style>` из `tokens.css` и внедрение через `st.markdown(..., unsafe_allow_html=True)`.
  2. Использование кастомных HTML-компонентов из `components.py` (`render_kpi_card`, `render_action_card`, `render_status_badge`).
  3. Настройка Plotly-графиков через `get_plotly_template()` с использованием семантических цветов из `tokens.json`.
- **Преимущества**: Сохранение 100% существующей кодовой базы и всех 649 тестов pytest без изменений протоколов передачи данных.

### Сценарий B (Целевой / Production Enterprise): Decoupled React 18 + Vite + Tailwind CSS + FastAPI
- **Трудоемкость**: Средняя (1–2 недели).
- **Архитектура**:
  1. **Frontend**: Одностраничное приложение (SPA) на React 18 / TypeScript / Tailwind CSS / Radix UI / TanStack Table / ECharts.
  2. **Связка токенов**: Прямой импорт `tokens.json` в `tailwind.config.js` через плагин `tailwind-design-tokens`.
  3. **Backend**: Оборачивание существующего ядра `inventory_dss` в REST/WebSocket API на FastAPI (эндпоинты `/api/v1/kpi`, `/api/v1/abc-xyz`, `/api/v1/forecast`, `/api/v1/suppliers`, `/api/v1/replenishment`).
- **Преимущества**: Мгновенный отклик интерфейса (<50ms), аппаратное ускорение анимаций 60fps, полноценная реализация клавиатурных шорткатов и поддержка многопользовательского режима.

## 6. Реестр граничных условий и защита от сбоев

| Код | Граничная ситуация | Поведение системы | Защитный механизм UI |
|---|---|---|---|
| **E01** | Переполнение склада ($V_{\text{used}} > 1000\text{ м}^3$) | Прогресс-бар визуально ограничивается $100.0\%$, чтобы не ломать верстку карточки. | Числовой текст выводит реальные $105.4\%$, плашка окрашивается в аварийную красно-черную штриховку. |
| **E02** | Нулевой спрос у нового товара ($\mu_D = 0$) | Формула $DOI = I_{\text{eff}} / \mu_D$ перехватывает деление на ноль. | Присваивается безопасное значение $DOI = 999.0$, SKU относится к некритичным, не вызывая сбоя рендера. |
| **E03** | Несогласованная матрица Саати ($CR \ge 0.10$) | Алгоритм AHP сигнализирует о противоречивости экспертных оценок. | Баннер предупреждает ЛПР, веса автоматически калибруются методом энтропии. |
| **E04** | Отсутствие интернет-соединения / CDN шрифтов | Недоступность Google Fonts (`JetBrains Mono`, `Inter`). | CSS-токены содержат безопасный системный стек: `monospace`, `ui-monospace`, `Courier New`. |
| **E05** | Экстремальные экраны (мобильные 320px) | Горизонтальный скролл таблиц. | Включается контейнерный скролл `overflow-x: auto;` с фиксацией ключевых колонок SKU. |
