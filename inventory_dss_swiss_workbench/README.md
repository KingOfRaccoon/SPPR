# Запас-Навигатор (Prescriptive DSS v1.5)

**Запас-Навигатор** — предписывающая система поддержки принятия решений (Prescriptive Decision Support System) для планирования закупочных волн, балансировки габаритов распределительного центра (РЦ) и стохастической оценки рисков цепи поставок.

Подробная спецификация математического ядра и бизнес-процессов: [`docs/PRODUCT.md`](docs/PRODUCT.md) · Видео-демонстрация: [`docs/demo/zapas_navigator_demo.mp4`](docs/demo/zapas_navigator_demo.mp4).

---

## Целевые роли и бизнес-эффект

| Роль | Решаемая задача в системе | Подтвержденный эффект |
| :--- | :--- | :--- |
| **Плановик поставок** | Расчет партий дозаказа по 6–50+ SKU с учетом кратности упаковки (`MOQ`), выравнивание по $\sigma$-норме в 1 клик | Сокращение времени подготовки волны с 2–3 часов в Excel до **3–5 минут** |
| **Начальник РЦ / WMS** | Контроль дискретных слотов рампы (`ceil` паллет по SKU), резерва ворот и тоннажа смены без перегруза приемки | Исключение очередей фур на доках и штрафов за простой транспорта |
| **Директор по закупкам** | Сравнение поставщиков по TCO (отпускная цена + требуемый страховой запас + риск срыва OTIF) и стресс-тесты плеча | Снижение потерь от дефицита критических позиций при сбоях логистики (+4 / +9 сут.) |
| **Финансовый директор (CFO)** | Прозрачный аудит «Цены бездействия» (Cost of Inaction), оборотного капитала волны и готовности пакета к 1С:ERP / SAP MM | Высвобождение до **15–22% избыточного оборотного капитала** при целевом SL 98.5% на критических SKU |

## Рабочие разделы (6 экранов + What-If симулятор)

1. **Ведомость заказа (`Alt+1`)** — главная таблица закупочной волны с roving-фокусом, KPI-полосой (паллеты, масса, бюджет, финансовый риск волны и дискретные WMS-слоты), выравниванием по `σ-норме` и карточкой балансировки «Было → Стало» с журналом причин (`Decision Trace Log`).
2. **Карта потоков (`Alt+2`)** — топология входящих отгрузок от заводов-поставщиков через РЦ к клиентским заказам, переключение линз (объем / стоимость / риск) и сквозная трассировка активного SKU.
3. **Габариты склада (`Alt+3`)** — управление потолками паллетомест, резервом ворот приемки, тоннажем и бюджетом волны; контроль дискретных WMS-слотов против дробных расчетных паллет и расписание смен рампы.
4. **Поставщики (`Alt+4`)** — матрица надежности OTIF и сроков поставки (`БалтКомплект`, `УралПривод`, `ВолгаПрибор`, `СеверСнаб`), расчет переговорного TCO-эффекта при смене поставщика (`SupplierNegotiationImpact`) и автоназначение лучших баз.
5. **Страховой буфер (`Alt+5`)** — пилообразный прогноз остатков (`Sawtooth Д+21`), моделирование задержек в пути (`0 / +4 / +9 сут.`), переключение резервных каналов (`Прямой ж/д`, `Региональный склад`, `Ускоренный авторейс`), стохастический $\sigma$-SS и оценка риска простоя.
6. **Спецификация CSV (`Alt+6`)** — предпросмотр и выгрузка готового пакета для поставщика и ERP: таблица `.csv` (разделитель `;`) и пояснительная записка с блоком **P&L и стохастического аудита волны** + маркером готовности OData.
7. **What-If Split-Screen симулятор (`Alt+S`)** — изолированная песочница сравнения «Текущая волна (База)» против «Стресс-сценарий (баланс)» без мутации основного стора до нажатия «Применить сценарий к волне».

## Математическое ядро

- **Стохастический страховой запас ($\sigma$-SS и ROP):** учитывает целевой уровень сервиса по приоритету позиции ($SL = 98.5\%, Z = 2.17$ для `critical`; $SL = 92.0\%, Z = 1.41$ для `standard`), вариативность спроса ($\sigma_D = D \cdot CV$) и дисперсию плеча поставки из надежности поставщика $R$:
  $$\sigma_L = L_{\text{eff}} \cdot \sqrt{\frac{1 - R}{R}}, \quad SS_{\sigma} = \mathrm{round}\!\left(Z \cdot \sqrt{L_{\text{eff}} \cdot \sigma_D^2 + D^2 \cdot \sigma_L^2}\right), \quad ROP_{\sigma} = D \cdot L_{\text{eff}} + SS_{\sigma}$$
- **Цена бездействия (Cost of Inaction, тыс. ₽):** агрегирует ожидаемый ущерб от остановки линии (`180 тыс. ₽/сут.` для `critical`, `38 тыс. ₽/сут.` для `standard`), наценку экстренного авторейса и штраф за срыв клиентского OTIF при недопокрытии $ROP_{\sigma}$.
- **Дискретные слоты WMS:** исключает ошибку «дробных паллет» при планировании рампы — каждый SKU резервирует целое число паллетомест $\sum \lceil Q_i / \text{unitsPerPallet}_i \rceil$.
- **MOQ-совместимый балансировщик склада:** при укладке заказа в лимиты паллет, массы и бюджета соблюдает шаг кратности поставщика (`minBatchQty`), дозаказывает позиции с риском дефицита и срезает избыток начиная с наименее рисковых строк, записывая бизнес-обоснование каждого шага.

## Горячие клавиши

| Сочетание | Действие |
| :--- | :--- |
| `Alt + 1` … `Alt + 6` | Мгновенный переход между разделами рабочей тетради (1 — Ведомость … 6 — Спецификация CSV) |
| `Alt + S` | Открыть / закрыть Split-Screen симулятор **What-If** |
| `Alt + B` | Сбалансировать текущую закупочную волну под ограничения РЦ и бюджета |
| `Ctrl + K` / `⌘ + K` | Командная палитра быстрого поиска разделов, пресетов и действий (WAI-ARIA Combobox) |
| `Ctrl + Z` / `⌘ + Z` | Отмена последнего действия (`Undo` со стеком до 20 снимков состояния) |
| `↑` / `↓` | Навигация по строкам таблиц SKU с мгновенным переключением инспектора (`roving tabIndex`) |
| `Enter` / `Space` | Выбор сфокусированной строки или элемента управления |
| `Escape` | Закрытие открытых модальных окон и командной палитры |

## Быстрый старт и сборка

Требования: **Node.js 20+**. Приложение работает полностью локально (`Zero-Backend / Local-First`), сохраняя состояние волны в `localStorage`.

```bash
# Установка зависимостей
npm install

# Запуск dev-сервера (Vite 6 + React 18)
npm run dev

# Проверка типов TypeScript
npm run typecheck

# Сборка автономного однофайлового бандла dist/index.html
npm run build:sandbox

# Экспорт и production-сборка стандартного Vite-приложения (dist-vite/)
npm run export:vite
```

## Формат интеграции с 1С:ERP и SAP MM (CSV / OData)

1. **Табличная выгрузка (`zapas_navigator_order.csv`, UTF-8, разделитель `;`):**
   - Колонки: `Позиция;Категория;Поставщик;Партия_шт;Паллеты;Масса_кг;Сумма_тыс_руб;Срок_дней` + контрольная строка `ИТОГО ПО ВОЛНЕ`.
   - Готова к прямому импорту в документ *«Заказ поставщику»* (1С:ERP Управление предприятием 2.5) и транзакцию `ME21N` / LSMW (SAP MM).
2. **Пояснительная записка и OData-маркер (`zapas_navigator_memo.txt`):**
   - Содержит сводку укладки склада, постатейную спецификацию, блок **P&L и стохастического аудита волны** (`WMS дискретные слоты рампы`, `Совокупный остаточный риск бездействия`, `Оборотный капитал`, `ТСО волны`, `Расчетная экономия ОК за год`) и явный флаг допуска к отправке в шину OData (`ДА — заказ в лимитах, статус APPROVED`, `ВНИМАНИЕ — габариты в норме, требуется закрытие дефицита`, либо `НЕТ — превышен лимит приемки РЦ`).
